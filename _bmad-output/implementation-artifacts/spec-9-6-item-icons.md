## Intent

**Problem:** The eight item icons exist only as an approved picture and a PowerShell grid; the OLED roulette (Story 9.7) has nothing to read them from.

**Approach:** Extend `scripts/make_item_icons.ps1` so the same grids also generate a small icon ROM module (`rtl/item_icon_rom.v`) and the two `.mem` data files used by the bench. A bench reads every pixel of every icon and checks the ROM against the data files.

## Boundaries & Constraints

**Always:**
- The art does not change: the grids and colours in the script stay as approved, and the regenerated preview sheet must match `docs/v2-item-icons.png`.
- Icon order is fixed: 0 low gravity, 1 invincibility, 2 time bonus, 3 reverse gravity, 4 high gravity, 5 zero gravity, 6 invert controls, 7 fog of war.
- Each pixel is a 2-bit index (0 black, 1 frame, 2 and 3 the icon's colours); each icon has a four-entry RGB565 palette; frames are green (0x0640) for icons 0 to 2 and red (0xD800) for icons 3 to 7.
- The ROM is generated Verilog (like `font_rom`), uses LUTs only (no block RAM, no DSP), and answers one clock after the address.

**Never:**
- No instance in the top level yet (Story 9.7 uses it); no change to `labyrinth_pkg.vh`; no new OLED or render behaviour.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Read a pixel | icon 0..7, x and y 0..15 | `idx` and `rgb` one clock later, equal to the data files | N/A |
| Frame | x or y at 0 or 15 | index 1 and the green or red frame colour | N/A |
| Background | index 0 | black (0x0000) for every icon | N/A |
| Address changes every clock | consecutive different pixels | each output matches its own address (no stale data) | N/A |

## Design Notes

Row words keep the ROM small: 8 icons x 16 rows = 128 words of 32 bits (pixel 0 in the top two bits); the pixel is a 16:1 select. `rgb` is the palette of the icon selected one clock earlier, so address and data stay aligned.
